## 一、需求定位

个人自用、不上架的悬浮窗实战助手。核心需求链条:

1. **对局中**:自动识别JJ 象棋局面,实时给三条带评分的候选走法,
   打吃/将军显著标注——决策辅助而非代打
2. **对局后**:一键封存,逐局面深搜复盘,量化失误;同局面下次秒回
3. **长期**:知识库越用越厚,推荐质量随复盘积累提升
4. **可用性**:完整闭环零手工干预(除封存按钮);卡死必须可事后回溯

## 二、已实现功能(实机验证通过)

### 1. 引擎域(Pikafish + NNUE)
- JNI 直驱 Pikafish,NNUE 64MiB 随包分发;Threads=3/MultiPV=3/Hash=64
- `SearchController`:限时搜索(800ms)挂起函数,MultiPV 候选解析
  (评分/杀棋/深度/PV);**searchMutex 串行化**——autoLoop 热搜索时
  复盘必须 `cancelAndJoin` 等它退出,杜绝两次搜索交错污染引擎状态
  (曾表现为对局中途整体卡死)
- 非法局面域:缺王 FEN 拦截 + `set_position` 返回值检查
  (Pikafish 缺王断言 SIGABRT 防御)
- **NNUE 就绪门(2026-10-22)**:`nativeInit` 等 `set_on_verify_network`
  置位后再返回(10s 超时),杜绝首搜抢在权重加载前;`SearchController`
  对退化结果(深度≤1/单候选/评分0 且非杀)延迟 300ms 重搜一次。
  旧版首推固定「兵九进一 +0.0」即此竞态
- **搜索收尾门(2026-10-22)**:每次搜索前后 `wait_for_search_finished`,
  候选按 root move 去重(深度高者优先)——修 stop 收尾残留串进下一轮,
  表现为同一着法两条推荐、评分不同;新增 `fast search` 日志留证
- **搜索时限修复(2026-10-23)**:JNI 直调 `Engine::go` 时补
  `limits.startTime`。旧版 startTime=0 使时间检查立即 stop,每手搜索
  只有 29-90ms/depth 3-7,复盘标称 3000ms 实际 30-50ms;修复后按
  movetime 真跑(游戏约 600ms、复盘约 3000ms),知识库深度恢复
- **冷启动预热(2026-10-22)**:service `onCreate` 后台 `ensureController`;
  autoLoop 不再同步等待引擎;引擎启动后先跑 60ms 开局 warm-up。
  NNUE 64MiB 在模拟器加载约 10s,点开局后首推延迟主要来自这里

### 2. 截屏识别域(2026-10 方案 A:CNN 主路)

- MediaProjection + ImageReader,双帧差分稳定检测(动画结束信号)
- **动画感知采集(2026-10-23,S1b)**:`CellSampler` 在投屏线程直接采样
  90 格(20fps,木色+格心指纹+白/红标记,不转 Bitmap),`MotionTracker`
  切 STABLE/MOVING/PLATEAU/SETTLE;非装饰格安静 160ms 落定,落定帧
  直接送识别,不再盲等 350ms×2;单格且前后都暖=点选抬起/光圈,不算走子;
  落定帧队列上限 3;采集异常自动回退旧双帧路径
- 校准式棋盘定位:四角标定 + 线吸附精化,按目标 App 持久化
- **逐格分类主路 = MobileNetV3-Small@128(RGB) + ONNX Runtime Mobile**:
  - `RecognizerEngine` 策略接口;`CnnEngine` 为唯一实现,
    `RecognizerEngineFactory.resolve()` 不再回退 NCC
  - 输入 3×128×128 通道平面,`(x/255-mean)/std` 逐通道归一化,
    与训练 PIL `BILINEAR` 同源的 4 邻点双线性重采样(`FrameSampling`)
  - **单次前向,不做翻转 TTA**(镜像汉字属分布外,会制造幻影)
  - 懒推理:dirty≥40 格才全盘扫描,否则只重推理指纹变化的格
  - 保留 `NccEngine` 源码但已退出全部运行路径(无影子对照、无回退)
- **仲裁层(AnchorRecovery + BoardWatcher + AutoLoop)**:
  - 分层置信:CONFIDENT≥0.9 / WEAK 0.75-0.9 / UNKNOWN<0.75;
    静态拒判回填、变化拒判走推测或作废
  - `speculate()`:2-4 个变化格须能解释成 1-2 步合法走法(容 1 格噪声),
    `XiangqiRules` 校验,结果盘面再做同型上限计数
  - 同型棋子上限 + **期望局面核对**(2026-10-22):超限先按棋谱回放/
    recorder/START 逐格核对,仍超限整帧作废+强制重推——**绝不按 margin
    删真子**(少子根因);期望有、本帧空只在"该格仍是木色棋子"
    (`R-B>40` 占比≥0.25)时补回(`BoardRepair.restoreMissing`),
    冷色空盘=真被吃/走开,不复活
  - **颜色门(2026-10-22)**:格内最暗 18% 笔画 `R-G` 纠红黑(红圈套黑子);
    指纹 5×5+颜色项;可疑格 `invalidate` 强制重推
  - **终局可信门(2026-10-22)**:绝对下限=双王(2 子)+相对门"本帧子数 ≥
    期望局面子数-2";修 9 子残局被 `MIN_PIECES=10` 拒绝导致吃子不记账、
    纠错后悬浮窗仍不出推荐
  - **期望可信门(2026-10-22)**:期望与本帧高置信格冲突>8 视为过期，
    不参与子数门/补子/超限核对；期望来源优先 `recorder.lastFen()`(含纠错)、
    回放只作后备
  - **多步歧义确认 + 样本飞轮(2026-10-26,S3)**:`SequenceSolver.solveAll`
  枚举多解 → 平台变化格打分消歧 → 仍歧义弹窗列候选序列让用户点选
  （不是四下拉）；确认/纠错帧 + 正确盘面落盘 `files/labels/`，作为下一轮
  重训难例；拒帧在 `files/dump/` 旁附 `.json`（原因+期望局面）
- **引擎 900ms + 深度日志(2026-10-26)**:实战 movetime 600→900ms，
  每次搜索记录 depth/耗时，评估质量与 movetime 是否生效
- **多步序列还原(2026-10-23,S2 后半)**:`SequenceSolver` 1-4 步合法 DFS,
  重启/暂停后连走多手也能还原记账(旧版只能 1-2 步,解释不了就留缺口丢步)
- **识别/引擎解耦(2026-10-23,S2 前半)**:`dispatchAnalysis` 独立 job +
  conflated 最新局面(`latestAnalysisFen`),识别循环不再 await 引擎;
  边条指纹单帧误判时用 `deferredSettle` 下轮重试,不再丢步
- **循环重启对齐(2026-10-22)**:重试/纠错/服务恢复的首帧先尝试把
    与棋谱的差异解释成 1-2 步合法走子并补记；解释不了则以识别盘为当前
    局面并留"棋谱缺口"，绝不静默跳过
  - **静止画面复用上一帧(2026-10-22)**:ImageReader 静止不推帧时不再
    空等/显示「等待稳定」，直接用上一帧识别，局面不变保持推荐
  - 落定确认期:连续两帧一致才出首推;开局近 START 且不足 32 子继续等,
    **30s 不再强制接受残缺盘**
  - 三处自动逃生门:vanish-only×10 用木色占比区分"误读(保留锚点重推)"
    与"真消失(当前帧重锚, recorder 只更新当前局面, 历史棋谱保留)";
    implausible×3 / failRun×5 保留锚点/棋谱 + 强制重推
- **前台 App 判定双轨**:UsageStatsManager 主轨(事件缺失时返回 null)
  + JJ 对局页边条灰度指纹兜底(一致率≥0.8,60 帧不符自动重学),
  非对局前台暂停识别且不清锚点
- **安装/版本事件自动清盘**:重装后不再需要手工点「结 & 下一局」
- 校准/识别失败帧落盘与 6 点像素 probe 日志,供 PC 端同帧对拍
- 循环层鲁棒性(识别层之上的纪律,屡试不爽):
  - 双向遮蔽容忍:仅消失=忽略;仅出现=修正锚点
  - 幽灵步三层防御:按移动子实际颜色归因、重置后确认期、
    局面异常时显式提示
  - 双步分解:AI 秒回吃掉刚走的子(一帧两步)也能正确记账


### 3. 悬浮窗助手域
- 藏蓝渐变标题栏 + 推荐列表 + 上一手行 + 降级状态条(琥珀+重试按钮)
- **标题栏四态闭环（2026-10-23）**：`局前(只有开局) → 点开局 → 局中
  (纠|实|结) → 点结 → 复盘中(复盘X/Y) → 完成/失败 → 局前(只有开局)`。
  旧版局前同时显示「开局+结」、复盘完显示「下一局」，状态语义混乱；
  失败或无棋谱也回局前态并落 `SealReview: ... back to idle` 日志。
  默认贴屏幕最左、整体尺寸缩小(标题13sp、按钮12sp、推荐13sp、徽章20dp)
- **Android 14+ 投屏适配（2026-10-26）**：先启动 mediaProjection 前台服务
  再创建投屏，并注册 `MediaProjection.Callback`；`onDestroy` 释放投屏；
  主圆钮跟随状态（开始/停止）；「导出日志」一键到 `下载/象棋助手日志/`；
  进程启动即开 AppLog（授权页等早期崩溃也留证）
- **首推库优先（2026-10-23）**：知识库命中不再等引擎——不阻塞拿到库着法，
  引擎就绪后 `scheduleBookFill` 后台补齐另两条（写回前核对局面未变）。
  实测点开局首推由 18s 降到约 1s；无库命中才等引擎加载
- 吃/将徽章:打吃=藏蓝「吃」圆牌,将军=朱红「将」圆牌,着法同色加粗
- 执方自动判定(双王行位比较),手动「黑/红」一键纠正
- 收起为圆点(轮到你=藏蓝实心,对手回合=灰白描边),标题栏短按收起
- **记谱口径**:双方纵线号统一从屏幕右侧数 1-9(用户要求与红方同向),
  红方汉字黑方阿拉伯数字;上一手按走子方显示「你：/对手：」
- **结 → 复盘 → 下一局闭环**:封存入库 → 逐局面 3000ms 深搜(模拟器
  实际约 6s/次)→ **悬浮窗按钮实时「复盘X/Y」+正文「已用 Ns」**
  → 朱红「下一局」→ 一键清谱重开,按钮复位
  (2026-10-23：进度落到按钮上，短局 1/1 也能看出已受理)
- **浮窗纠错(2026-10-22)**：局中标题栏「纠」→ 四个下拉
  `[红/黑棋子][起始纵线 1-9][进/退/平][目标纵线或步数]`；自动判断
  「补上漏的一手」或「改掉上一手」，写回棋谱与识别锚点后立即重出推荐；
  同弹窗带「撤回上一手」
- **实况页（2026-10-23 改）**：`launchMode=singleTask`，重复点「实」只把
  同一实例提到前台，返回一次即回主界面（旧版会叠多层）；棋盘永远
  **我执子在下**——执黑时上下翻转（只翻行不翻列，与 JJ 执黑显示一致），
  触屏纠正按视觉行反算，写入仍是规范局面
- **新对局（2026-10-23 改）**：局前标题栏只有「开局」——**局前不启动
  识别循环**（不抓帧/不跑 CNN/不提示识别不稳定），引擎后台静默预热；
  用户手点开局后以当前盘面为新局起点、清旧谱并开始记账。进程中途恢复
  且棋谱已有走子时仍自动续上识别。旧版"识别到完整 START 局面只清谱"
  与"未点就已记下第一步"自动切局中的路径随局前识别一起关闭
