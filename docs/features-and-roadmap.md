## 一、需求定位

个人自用、不上架的悬浮窗实战助手。核心需求链条:

1. **对局中**:自动识别JJ 象棋局面,实时给三条带评分的候选走法,
   打吃/将军显著标注——决策辅助而非代打
2. **对局后**:一键封存,逐局面深搜复盘,量化失误;同局面下次秒回
3. **长期**:知识库越用越厚,推荐质量随复盘积累提升
4. **可用性**:完整闭环零手工干预(除封存按钮);卡死必须可事后回溯

## 二、已实现功能(实机验证通过)

### 1. 引擎域(Pikafish + NNUE)
- JNI 直驱 Pikafish,NNUE 64MiB 随包分发;Threads=3/MultiPV=3/Hash=64
- `SearchController`:限时搜索(800ms)挂起函数,MultiPV 候选解析
  (评分/杀棋/深度/PV);**searchMutex 串行化**——autoLoop 热搜索时
  复盘必须 `cancelAndJoin` 等它退出,杜绝两次搜索交错污染引擎状态
  (曾表现为对局中途整体卡死)
- 非法局面域:缺王 FEN 拦截 + `set_position` 返回值检查
  (Pikafish 缺王断言 SIGABRT 防御)

### 2. 截屏识别域
- MediaProjection + ImageReader,双帧差分稳定检测(动画结束信号)
- 校准式棋盘定位:四角标定 + 线吸附精化,按目标 App 持久化
- NCC 模板识别:BOX 块均缩放 + 归一化 + 中心圆掩码 + 红黑硬门;
  白光圈/红色落子标记像素预剔除
- **循环层鲁棒性(识别层之上的纪律,屡试不爽)**:
  - 双向遮蔽容忍:仅消失=光圈脉动遮蔽帧,忽略;仅出现=恢复帧,修正锚点
  - 幽灵步三层防御:按移动子实际颜色归因(不盲信轮次)、重置后确认期、
    局面异常时悬浮窗显式提示而非沿用旧候选
  - 缺王帧用锚点王格复用修复;王格被同色子误占也修复;王格出现敌子
    (真被将死/吃掉)则拒绝修复
  - 不可能兵位修复(点击抬起棋子被误读成不可能位置的兵卒)
  - 双步分解:AI 秒回吃掉刚走的子(一帧两步)也能正确记账

### 3. 悬浮窗助手域
- 藏蓝渐变标题栏 + 推荐列表 + 上一手行 + 降级状态条(琥珀+重试按钮)
- 吃/将徽章:打吃=藏蓝「吃」圆牌,将军=朱红「将」圆牌,着法同色加粗
- 执方自动判定(双王行位比较),手动「黑/红」一键纠正
- 收起为圆点(轮到你=藏蓝实心,对手回合=灰白描边),标题栏短按收起
- **记谱口径**:双方纵线号统一从屏幕右侧数 1-9(用户要求与红方同向),
  红方汉字黑方阿拉伯数字;上一手按走子方显示「你：/对手：」
- **结 → 复盘 → 下一局闭环**:封存入库 → 复盘(失误/大漏着)→
  朱红「下一局」→ 一键清谱重开,按钮复位

### 4. 主界面域(墨纸编辑部版式,v4)
- 纸底报头(弈枰大字+朱红竖规+CHESS STUDIO 小注)+双细线
- 黑细线直角棋盘(旧纸底),BoardView 墨色网格线
- 工具全文字化:选子下拉 / 摆开局 / 清空 / 换先 | 校准 | 识别
- 目录式下划线操作行 + 右下朱红大圆主按钮
- 结果卡带用途提示(分析引擎输出区,空态不再是黑框)
- 摆开局真重置(START 模板不可变,手摆不污染)

### 5. 可观测性域(AppLog,2026-10-13)
- 全量业务日志双写:logcat + `files/logs/` 会话文件(保留 4 份)
- 内存环形缓冲 2500 行;uncaught 崩溃堆栈同步落盘
- 卡死关键锚点:识别循环兜底(异常顶悬浮窗)、结/复盘分支、
  慢搜索(>movetime+2s)与空 bestmove

## 三、路线图

### 近期(有明确入口)
1. **真实卡死样本回放**——等用户下一次"下一半卡死",用 AppLog 日志
   定位是识别循环、引擎互斥还是 UI 层;此前勿凭猜测改架构
2. **红帅格 NCC 窗口污染(高优先)**——实测黑車贴邻红帥(间隔1格)时,
   黑車黑环+阴影侵入识别窗口,NCC 全线劣化(真模板 d≈0.6,正常≈0.35,
   EMPTY 反而最近)→ 红帅误读黑炮。已量化诊断:tools/diag_cell.py
   (定点输出某格 NCC 距离排序/红占比/红质心偏移);修复层已兜底
   (王格被异色子占也放回王)。根因迭代方向:中心掩码半径缩小实验/
   ±2px 多偏移采样投票/棋子块紧致分割,需先在 PC 端用落盘帧批量
   验证再上机
3. **红车误配色根因**——实测对局中红车被 NCC 配成黑车(产生
   "黑3车红0车"非法 FEN)。棋子上限校验已拦截伤害,但根因在
   颜色硬门(REDNESS_GATE=40)对 JJ 深色皮肤/光圈下的红字区分度,
   需采样分析 d 与红色占比分布后再调或换红黑判据
4. **马象士三连闪**——AI 底线相邻三子成组消失又复现(同一局实测),
   与黑車贴邻+皮肤相关,疑似同属窗口污染族,随 #2 一并诊断
5. **多目标 App 校准**——TARGET_APP 固定 "default",扩展为按包名多套
   校准/模板(存储已按 target 分目录,差一个选择入口)
6. **识别成功跳帧**——局面哈希未变时跳过重识别与重分析,省电
7. **悬浮窗位置约束**——拖动时限制进识别区,防用户拖进棋盘后误判遮挡
