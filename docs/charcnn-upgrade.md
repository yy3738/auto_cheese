## 一、为什么换识别核心（NCC 的实证弱点）

NCC 模板匹配是"定死"的（JJ 默认皮肤采样一次），只对线性亮度变化鲁棒
（norm24 归一化已解决），对**叠加类污染完全无能为力**。实测三类误读全部
出自这儿：

| 异常事件 | 机制 | 实测证据 |
|---|---|---|
| 红帥判空/读成黑炮红王 | 白色行棋光圈罩住棋子，removeWhiteOverlay 把窗口洗成均匀色块 → std 判空；或洗淡特征 → NCC 全线模糊（最近模板 EMPTY 0.58/黑王 0.59/黑炮 0.60，正常局红帥 d≈0.1-0.3） | diag_cell.py 输出、红K=0 循环日志 |
| **红车被读成黑车/红炮被读成黑炮**（色翻转） | 红黑硬门 REDNESS_GATE=40 二值化：红子被光圈压色跌破 40 → 归入黑方候选 → 同形黑子一拍即合 | 「(0,5)红车→黑车」伪装成「车→车」的 two-steps 日志 |
| 黑马/象/士三连子成组闪烁 | 底部装饰阴影+棋子叠加使 std 在 32 判空阈值摇摆 | 每 1.3s vanish/appear 交替日志 |

共同根因：**二值化硬决策**（std<32、redness≥40、最近模板）遇上渐变类污染
时的脆弱。修复层（锚点恢复/vanish 吞帧）是止血，不是治病。

## 二、Route A：棋谱回放盘面的单格分类器

### 结构（与现有七层识别链的对接）

只替换 ③ 逐格识别的「红黑门+模板匹配」核心，其余层次全部保留
（稳定帧检测/网格/可信门/归一化/锚点修复/循环分类原样）：

```
任一截图 → 校准网格裁格(已有) → 逐格小 CNN 分类(15+1 类,含空格)
  → 90 格棋子数组 → 可信门 → 归一化 → 修复层 → 循环层(不变)
```

### 模型
- 输入 32×32 灰度（裁好的格图 resize）
- 3 层 conv（1→16→24→24, 3×3）+ 全局池化 + 全连接 15 类
- <20K 参数，CPU 推理 90 格 <100ms（vs NCC：90 格 × 20 模板 × 位移搜索）
- 训练脚本：`tools/train_charcnn.py`（PyTorch CPU，已装 torch 2.8.0+cpu）

### 数据增强（针对三类历史误读源定制）
1. **白圈叠加**：随机位置画 α0.35-0.6 白圆盘（半径 28-42%）——模拟行棋光圈
2. **暗环叠加**：棋子边缘叠暗环——模拟将军特效
3. 亮度 ±25 / 对比度 ×0.75-1.25 / 平移 ±3px / 旋转 ±8°
4. 每类每 epoch 均衡采样（EMPTY 降采样，少数类过采样）

## 三、数据集现状（samples/dataset/，1150+ 张）

**采集管线**（全程半自动，用户只需校对）：
```
截图(screencap) → tools/crop_cells.py <截图> <tag>
  → samples/<tag>/{r行c列}.png + montage.png(校对图,自动粗标已印在图上)
→ 用户回复错误的格(格式 "行,列=真子",中文类名如 "0,2=红马")
→ tools/finalize_labels.py <tag> "0,2=红马" ...
  → 正确标注拷入 samples/dataset/<类>/，模糊且未纠正的跳过(防污染)
```

**JJ 标记语义**（校对时必读，来自用户确认）：
- 白圈 = 刚走完的那步的**起点空格**（若圈下有棋子视作污染样本）
- 红圈 = 刚走完的落点/威胁标记（不污染识别）
- 绿圈 = JJ 提示"下一步可吃/目标"的标记棋子

**已采集**：5 局截图（shot1-6 为常规对局+局终弹窗，shot7-11 为残局）
**当前分布**：黑卒 44 / 红兵 38 / EMPTY 708 / 黑±24 红±20 / 黑馬 18 /
红炮 15 / 黑車 16 / 红王 11 / 红马 10（⚠ 最少）
**已确认的错标模式**（训练集里的珍贵样本）：红帅被标黑士×2、红炮被标
黑炮×2、红车被标黑卒×1、白圈被标黑马×1——全部已由用户纠正落库
