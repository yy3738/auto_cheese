# 使用文档

> 弈枰 · 实战悬浮助手。个人自用,不上架。版本对应 2026-10-13 的 develop。

## 0. 安装与启动

```
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

首次启动都会看到**墨纸编辑部级主界面**：报头「弈枰」+ 黑细线棋盘 +
右下角朱红大圆「开始实战辅助」。

| 主界面元素 | 作用 |
|---|---|
| 摆开局 / 清空 / 换先 | 摆盘工作台：恢复初始局面 / 清空棋盘 / 交换行棋方 |
| (擦除)+棋子名下拉 | 选画笔：选中后点棋盘空点即可摆子 |
| 校准 | 标定目标棋盘 App 的棋盘四角（首次必做） |
| 识别 | 截屏一次并进识别工作台核对模板 |
| 对局复盘 → | 查看历次封存对局的复盘明细 |
| 分析当前局面 | 对主界面棋盘直接做引擎分析,结果显示在底部结果卡 |
| 开始实战辅助（朱红大圆） | 启动/停止悬浮窗实战助手 |

## 1. 首次使用流程（重要：授权的两段式）

1. 点「开始实战辅助」→ 弹出截屏权限页 → 勾选后允许「立即开始」
2. **回到主界面后再点一次大圆钮**——授权有效但服务尚未启动,
   第一次点击只会弹提示「授权后请再点一次此按钮」
3. 出现「已开启自动识别」提示即成功,切到 JJ 象棋对局

> ⚠️ 重装 APK 或杀进程后此流程要重走（MediaProjection 授权随
> 进程失效,系统限制,无法自动恢复）。

## 2. 校准（每个目标棋盘 App 一次）

1. 点「校准」→ 3 秒倒计时内切到 JJ 对局界面（棋盘完整可见）
2. 自动抓屏后弹出悬浮「校准」按钮,点击进入标定页,依次点棋盘四角
3. 保存后自动做棋盘线吸附精化;结果存 `files/calib_default.json`

校准过的 App 之后无需重复。若识别出现**单格持续误读**（其余全对）,
优先怀疑校准文件坏了而不是识别算法——删掉重校。

## 3. 对局中使用悬浮窗

悬浮窗默认停在棋盘下方中央（避开识别区）,可拖动。

- **标题栏**：`弈枰 | 黑 | 结 | ✕`。点「黑/红」可手动翻转执方
  （一般是自动识别的,识别错时才用手动）;点「结」封存复盘;
  标题栏空白处点一下收起为小圆点,再点圆点展开
- **推荐区**：三条候选,普通=灰色序号,打吃=藏蓝「吃」徽章,
  将军=朱红「将」徽章;首行常年显示上一手（「你：炮二平五」/「对手：…」）
- **降级条**：识别不稳定时出现琥珀色「识别不稳定，正在等待画面…」+
  「重试识别」按钮,稳定后自动恢复候选
- **下一局**：复盘完成后「结」会变成朱红「下一局」,点它清棋谱开新局,
  按钮复位为「结」

## 4. 复盘与知识库

- 对局中任意时刻点「结」（棋谱非空）→ 入库 → 逐局面 3 秒深搜 →
  悬浮窗显示「失误 N 大漏着 M」;明细在主界面「对局复盘」列表里看
- 复盘分析过的局面自动进知识库:同一局面再次实战出现时,悬浮窗
  秒回（「kb hit」）,不占引擎
- 封存后务必点「下一局」再开新局,否则旧棋谱会被继续追加

## 5. 卡死 / 异常排障（内置日志）

所有业务日志自动落盘（`files/logs/app-MMdd-HHmmss.log`,保留最近 4 份,
崩溃堆栈也写在内）。卡死后**不要杀进程**,直接拉日志:

```bash
# 列出日志
adb -s 127.0.0.1:5555 shell "run-as com.cheese.assistant ls -t files/logs"
# 导出最新一份
adb -s 127.0.0.1:5555 exec-out run-as com.cheese.assistant \
  cat files/logs/<文件名> > 弈枰日志.txt
```

把文件发给分析。识别卡死时悬浮窗降级条通常会直接显示原因
（「识别循环异常：…」）。

## 6. 已知限制

- 重装/杀进程后截屏授权失效,必须重走第一节流程（系统限制）
- 校准按目标 App 区分,但当前固定只支持一个目标（TARGET_APP="default"）
- 悬浮窗别拖进棋盘识别区（y≈455~1530）,会遮挡识别出持续 unknown
- JJ 让红方在屏幕上方时（我方执黑）识别会自动上下翻转,无需手动干预;
  若执方显示反了,点标题栏「黑/红」手动纠正
